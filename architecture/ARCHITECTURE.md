# V1 architecture inventory

Product: **AgentDock** — manage Agent skills and MCP resources; observe Harnesses.

Harnesses are discovery sources, not deployment targets. V1 writes only:

```
USER     %USERPROFILE%\.agents\skills
PROJECT  <repo>\.agents\skills
```

App metadata (SQLite, cache, logs) stays in the legacy `~/.skills-manager` path. This is intentional compatibility state, not a skill library; the product/CLI name is AgentDock while existing data remains addressable after upgrade.

The active AgentDock icon set is generated by `scripts/generate-agentdock-icons.py`; the previous S mark remains only in `*-v1` reference files. Windows keeps the old WiX upgrade code and main executable filename during the installer migration window; macOS keeps the old internal bundle name while exposing the AgentDock display name; Debian/RPM packages replace or obsolete the old `skills-manager` package.

## Compatibility and cleanup

The canonical writer remains the only active Skill mutation boundary. `core/central_repo` still owns SQLite, cache, logs, and the legacy `~/.skills-manager` compatibility base; it is not a second Skill library. The desktop has no startup CLI bridge or filesystem watcher; CLI discovery is explicit through installation/PATH. Migrations v9 and v10 remove retired remote-sync/updater/tray preferences, the merge-conflict projection, deployment-era target rows, and obsolete linked-workspace records while preserving Skills, tags, Presets, projects, and canonical paths.

Manual update checks and explicit Adopt/replace flows remain source-aware. An existing Adopt target opens a `SKILL.md` diff before Replace, and locally modified managed copies are not overwritten. The desktop is Windows-first; other platform build jobs are retained only as packaging compatibility until the product surface is narrowed further.

## Skill status

`Managed` | `Discovered` | `Read-only` | `System` | `Conflict` | `Update available`

Same name, different path → two rows. Never collapse. Skill inventory state (ignored, hidden, and a local note) is keyed by normalized resource path; MCP state is keyed by the full inventory row id (harness + server + config identity), so servers sharing one config remain independent. The same builders back the desktop and `inventory state` CLI command.

## MCP V1

Inventory only. Transports: `stdio` | `streamable-http` | `legacy-sse` | `unknown`. Rows retain source/config identity but never expose command, args, environment, headers, or raw config to the WebView. No enable/disable or writeback.
